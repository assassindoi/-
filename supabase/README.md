# 先生としまの共有設定

この設定が終わるまでは、アプリの「先生としま」は同じブラウザ内のお試しモードです。画面上の役割切り替えは本人確認ではありません。共有設定を終えると、メールログインとDB側の権限で先生・しまを区別します。

## 1. 共有先を作る（先生のみ）

1. https://supabase.com/dashboard にログインし、新しいプロジェクトを作成します。しまが Supabase の管理者アカウントを作る必要はありません。
2. プロジェクトの SQL Editor を開き、新規クエリで、このフォルダの `schema.sql` の全文を実行します。既存プロジェクトを使う場合も tone_ で始まるテーブルと非公開バケットを追加します。先生・生徒のポリシーとトリガーを省略しないでください。
3. Authentication の URL Configuration で Site URL と Redirect URLs に `https://assassindoi.github.io/-/` を設定します。メールログインを有効にします。開発時のみ `http://localhost:5173/` も追加できます。
4. プロジェクト設定の Data API URL と publishable キー（旧 anon キーでも可）を確認します。アプリの「先生としま」→「アカウント」→「二人の共有先を設定」に入力します。**service_role / secret キーはブラウザに入力しません。**

URL と公開キーは、しまの端末にも同じものを設定します。公開用キーはサーバー管理用の秘密鍵ではありません。データへのアクセスはログインとルーム参加により制限されます。

## 2. 二人を登録する

1. 先生がアプリで自分のメールアドレスを入力し、届いたログインメールのリンクを開きます。
2. 先生は「先生としてルームを作る」を押します。招待コードをしまに渡します。
3. しまは自分の端末で同じ共有先を設定し、自分のメールでログインします。
4. しまは「しまとして参加する」に招待コードを入力します。1ルームに生徒は1人です。
5. 先生が予定を提案し、しまが同意し、録音を提出し、先生が確認できることを二つの端末で確認してください。

メールが届かない場合は迷惑メール、Authentication の設定、プロジェクトのメール送信制限を確認します。継続利用にはカスタム SMTP の設定が必要になることがあります。秘密値は Supabase の設定画面に入力し、チャットには送らないでください。

お試しモードの記録は自動でアップロードしません。元の「参考音声」のファイルも自動では送信しません。先生が「練習素材」から選んで共有素材として追加します。共有した録音・画像・動画は非公開の Storage に保存します。アプリの表示は15秒ごとの再取得を基本とし、Realtime が有効な場合は変更通知でも更新します。

## 3. 通知

### アプリを開いている間

しまが予定とリマインドに同意し、アカウント画面でブラウザ通知を許可すると、開始時刻に通知します。ブラウザ通知は端末の通知設定にも依存します。各予定の「カレンダーに追加」も使えます。カレンダーのアラームは取り込み先の設定に従います。

### アプリを閉じている間（任意の追加設定）

この機能はコードの保存だけでは動きません。通知サーバー、定期実行、二人それぞれの端末登録が必要です。

1. Web Push の VAPID キーペアを管理者の端末で生成します（例：`npx web-push generate-vapid-keys`）。秘密キーは公開リポジトリやチャットに貼りません。
2. Supabase CLI で対象プロジェクトに接続し、`supabase functions deploy tone-reminders --no-verify-jwt` を実行します。`supabase/config.toml` と `functions/tone-reminders/` を使います。
3. Supabase の Edge Functions の Secrets 画面に以下を設定します。
   - `VAPID_PUBLIC_KEY`：通知用の公開キー
   - `VAPID_PRIVATE_KEY`：通知用の秘密キー
   - `VAPID_CONTACT`：管理者連絡先（`mailto:` の形式）
   - `TONE_CRON_SECRET`：十分に長いランダムな管理者専用の値
   - `SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` は関数側のプラットフォーム環境から取得します。ブラウザには渡しません。
4. Supabase で Cron / pg_net を有効にし、Vault に `tone_supabase_url` と `tone_cron_secret` を保存します。後者は関数の `TONE_CRON_SECRET` と同じ値です。
5. `schedule-reminders.sql` を一度実行し、毎分の定期送信を登録します。同じジョブ名で再設定するときは既存ジョブを確認してください。
6. 二人がアプリの共有先設定に `VAPID_PUBLIC_KEY` を設定し、ログインして「この端末にバックグラウンド通知を登録」を押します。
7. しまがリマインドに同意した予定を作り、先生・しまの端末で実配信を確認してください。登録ボタンの成功だけではサーバー配信の成功は確認できません。

開始通知は生徒へ、未確認の新しい録音提出は先生へ送ります。合意なし・リマインド同意なしの予定には送信しません。通知は遅延や失敗の可能性があり、練習の実行そのものを保証しません。ユーザーはアカウント画面で解除できます。

## データと評価の扱い

- 先生の必須メモ、評価、マップの条件は生徒から変更できません。先生が内容を変えた予定は、生徒の再合意が必要です。先生が生徒の代わりに合意する操作はDBで拒否します。
- 録音提出と先生の確認を分けます。提出済みは、自動で課題達成にはしません。
- 周波数の重心、スペクトル平坦度、高域比率から参考分類を表示します。喉頭位置、声帯の閉鎖状態、音色の良し悪しを断定する測定ではありません。
- 録音の比較グラフは各録音の最大値で正規化します。音量差の採点には使用しません。
- 鍵盤の測定結果は人が記入する記録です。マイクから音域を自動確定する機能ではありません。
- 音声・動画・画像は最大100MBです。共有先プラン側の上限が低ければそちらが優先されます。
- このアプリは練習を実行させることを保証しません。本人の合意と、先生による確認の記録を支援します。

## 検証済み範囲

ローカルブラウザで提案・合意・録音・提出・確認・課題・タグ・測定・振り返りを検証しています。模擬マイクによる録音・音響分析を含みます。DBスキーマは組み込み PostgreSQL でRLS・役割・別ルーム隔離・合意の保護を実行検証しています。

実プロジェクトの接続情報がない状態では、Supabase 本番でのメール配信、Storage、別端末同期、Edge Function の実行、Web Push の実配信は未検証です。外部設定後の確認が必要です。
